# TONDE contributor instructions

Before product/UX/domain/AI/persistence changes, read the authoritative [TONDE Product Constitution](docs/product/constitution.md), [glossary](docs/product/glossary.md) and [invariant register](docs/product/invariants.md). A conflict requires explicit repair or versioned amendment; never introduce a second product interpretation.

- One Master Production; Real/AI plans attach to its same Shots. Real Production is the default Studio face. Hybrid is per-Shot assignment.
- Setup = production equipment/software/tools; Assets = reusable entities; Settings = account/application preferences. Preserve the seven responsibility boundaries.
- Never fabricate unavailable-media analysis, false certainty, completed AI features, human approvals or hosted verification.
- Keep exact timing/authorization/order/status logic deterministic. AI reasoning returns scoped, validated proposals; consequential application requires creator authority and impact preview.
- Edit `product/vocabulary.json` and additive SQL migrations, then run `node scripts/generate-database-types.mjs`. Do not hand-edit generated frontend/Python vocabulary. Verify with `--check`.
- Run constitution and Prompt 1 foundation/security regressions. Record internally failed checks as failures and repair them; external credentials/provider configuration may be BLOCKED.
- Read [schema evolution](docs/schema-evolution.md) before schema changes. Do not rewrite applied migrations, bypass RLS or expose service-role credentials. A repair to an applied migration is a new forward migration (e.g. 029 exists because 010 left two guards `SECURITY INVOKER` and the server write path failed with `permission denied for function`; 030 exists because optimistic-concurrency conflicts raised SQLSTATE 40001, which PostgREST retries indefinitely, so a stale write never returned over HTTP). Never raise a bare class-40 SQLSTATE for a product decision: use the `PTxxx` prefix that maps to the intended HTTP status.
- Historical `legacy/` is not runtime, a fallback auth implementation or product documentation.
- Hosted state as of 2026-10-08: the linked development project was reconciled so the ledger records **001–030** and the hosted `tonde` effect state matches the source migrations. Forward rollout applied 015–030; 011–014 were repaired as **history only** and were never replayed. Equivalence is re-read from both sides rather than asserted: `node scripts/pre-prompt10-catalog-verify.mjs` compares every untruncated table/column/constraint/index/policy/trigger/function-body/type/ACL identity (`test-results/pre-prompt10/hosted-final-diff.json`; 0 differences after package 21). The expanded two-user acceptance runner (`scripts/pre-prompt10-hosted-verify.mjs`) covers populated cross-tenant reads/writes/deletes, all 145 RPCs, ten approval sets, the six private buckets and Auth session behaviour. What is still **not** accepted: real signup/verification/password-reset email delivery and Google sign-in (external inbox/OAuth credentials; admin-confirmed users prove nothing about delivery). The project requires email confirmation and declares no custom SMTP, so a real signup answers HTTP 429 `over_email_send_rate_limit`; Google is disabled with an empty redirect_uri; leaked-password protection is refused with HTTP 402 (plan-gated). Provider-backed AI/media generation remains unconfigured and unclaimed. Advisors: 0 ERROR, with 145 intentional `authenticated_security_definer_function_executable` warnings reviewed individually. See [runbook](docs/supabase-runbook.md), [certification report](docs/pre-prompt10-final-certification.md) and the migration matrix in the [Prompts 1–9 audit](docs/system-gap-audit-prompt1-9-final.md); passing local/mocked tests still do not prove hosted acceptance.
- Do not build later engines just because the constitution defines them. V1 identity describes the complete build-sequence target, not the current release.
